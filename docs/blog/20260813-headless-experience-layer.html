A Tuesday on the queue

You know the case. Payment failed on a renewal. SLA has two and a half hours left. The agent — human or otherwise — does not need a novel. They need the number, the customer, the burn, and the next move. In Lightning that is a component. In Slack it becomes Block Kit. In ChatGPT it becomes a paragraph you hope nobody misreads. In Claude it used to be the same paragraph, plus a spinner if you got ambitious.

Headless Experience Layer is Salesforce’s answer to that split-brain. You describe the interface once. The host paints it. This post is the version I wish I had on day one: what we built, what the repo actually recorded, and the exact path from an HXL mosaic to a card sitting in Claude chat.

What the playground actually is

The product page’s Explore the Playground button is not a marketing mock. It is a live Mosaic runtime. Every tutorial is itself a widget. Expand the code view on lesson one and you are reading the same JSON a host will render — Slack, ChatGPT, Claude, Agentforce, or any MCP host.

Three words the playground uses, and they matter
WordMeaning
ComponentA primitive. tile/text, tile/button, tile/card.
WidgetA composition of primitives. One page that is supposed to work everywhere.
MosaicThe JSON. Type = Model, Widget = View, Action = Controller.

You do not pick hex colors. You pick intent: primary, warning, elevated. Each host maps those to its own look. That is the whole trick, and it is why a card that started in the playground can look native in Claude without a second stylesheet.

The card we built

The playground already has cousins of this — case summary, SLA status, similar cases. We wanted the one a queue actually uses: what is it, is the SLA on fire, what do I do next.

The interesting line is not the heading. It is this:

{
  "definition": "tile/callout",
  "meta": { "if": "{!$case.slaAtRisk}" },
  "attributes": { "variant": "warning", "title": "SLA at risk" }
}

When the case is not at risk, that callout is not hidden with CSS. It is not in the tree. Claude, Slack, and Lightning can each decide what “absent” means on their surface.

Two envelopes, one idea. The playground file is mosaics/case-next-action.json. The org file is a WidgetBundle under force-app/main/default/uiWidgets/caseNextAction/ — {!$attrs.*} plus schema.json. Same primitives. Different wrapper so Salesforce can type-check it.

From HXL to Claude chat

This is the part that is not on the Salesforce marketing page. Building the mosaic is half the work. Getting Claude Desktop to mount the iframe is the other half. Here is the path we actually used.

1
Author the mosaic in HXL Paste or write JSON in the playground. Bind data with {!$case.field}. Keep variants semantic. Confirm it renders on more than one host preview.
2
Keep a WidgetBundle if you also want the org Three files, same folder: the lightning__agentforceWidget body, schema.json, and .uiwidget-meta.xml. Optional for Claude. Required if Agentforce in the org should show the same card.
3
Wrap it as an MCP app Claude chat does not load Mosaic JSON by itself. It calls a tool. This repo’s mcp/server.mjs exposes get_case_next_action and serves the card as text/html;profile=mcp-app. The tool returns JSON. The host fetches the HTML resource and puts it in an iframe. You must inline the MCP Apps handshake bundle — without it, Claude shows a spinner forever.
4
Register the server on the machine that runs Claude Desktop Native stdio, not an HTTP proxy. Point Desktop at node mcp/server.mjs. Quit Claude with ⌘Q and reopen. Then enable the tool in the chat composer. 
{
  "mcpServers": {
    "hxl-case-next-action": {
      "command": "node",
      "args": ["/absolute/path/to/hxl-agentic-experience-layer/mcp/server.mjs"]
    }
  }
}

That block lives in Claude Desktop’s claude_desktop_config.json (macOS: ~/Library/Application Support/Claude/). After npm install in mcp/, Desktop launches the server itself. You do not keep a terminal open.

Git in this repo has the result — the card in Claude chat, and a short zoom demo — with the account name and company mark blurred. It does not yet have a click-by-click recording of the Search and tools toggle. The steps below are that missing reel, written down.

Turn the MCP on in Claude Desktop

Claude Desktop will not show a new local server until it is fully restarted. Closing the window is not enough.

  1. Save the mcpServers entry above. Use a real absolute path to server.mjs.
  2. Quit Claude with ⌘Q. Reopen the app.
  3. Start a new chat. Old threads keep a dead iframe if you already failed once.
  4. Open Search and tools (the sliders / tools control next to the composer).
  5. Find hxl-case-next-action and turn it on.

If the name is missing, Desktop never loaded the config. Check the JSON comma, the node path, and the MCP log under ~/Library/Logs/Claude/.

Use it

In that new chat, send exactly this:

Show me the Case Next Action card

Claude should call get_case_next_action. Allow the tool if it asks. You want the white card — case number, High / SLA badges, the amber callout, Take next action — not a paragraph that says “here’s the card” with a spinner underneath.

Click Take next action if you want to see the widget talk back into the thread. In this sample the buttons are wired to a chat message, not to a Salesforce update. That is intentional — the demo stops at “the host can render and click,” not “we wrote the case.”

When the card is a spinner

We hit this. Claude called the tool. The model wrote a confident summary. The iframe sat on a loading asterisk. Two causes, both boring, both fatal:

  • The HTML never completed the MCP Apps handshake. Claude keeps the iframe visibility: hidden until the view sends ui/initialize. The widget HTML has to inline @modelcontextprotocol/ext-apps. A CDN import will fail the sandbox and look identical to “nothing.”
  • HTTP-through-mcp-remote. It listed tools. It even fetched the resource. The iframe still never appeared. Native stdio did.
If you already have a broken turn in the thread, do not keep prompting that chat. New chat after ⌘Q. The host caches the widget HTML aggressively.

Trust stays in the platform

Headless here means the presentation is portable. It does not mean the case data is a public JSON file. In a real org the same mosaic would bind through Salesforce metadata — sharing, FLS, audit — and Claude would be another surface, not a sidecar with a copy of the truth.

This sample uses a fictional Northwind payload on purpose. The deploy path is what we are sharing: mosaic → MCP app → Claude Desktop chat.

Clone hxl-agentic-experience-layer, npm install in mcp/, point Desktop at server.mjs, ⌘Q, enable the tool, ask for the card. That is the whole deploy.
