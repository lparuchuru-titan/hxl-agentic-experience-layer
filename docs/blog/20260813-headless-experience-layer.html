Start here: the card in Claude

If you have never heard of Headless Experience Layer, start with the picture, not the acronyms. A support case is on fire. Payment failed. SLA has two and a half hours left. The person — or the agent — does not need a paragraph. They need the number, the customer, the burn, and the next move. In this video that card is sitting inside Claude Desktop chat. We did not rebuild it for Claude. We described it once, then asked Claude to show it.

What you are watching: someone types Show me the Case Next Action card. Claude calls a tool named get_case_next_action. The white card appears — case 00001234, High, SLA at risk, Take next action. That is the product promise of HXL used in the wild: one interface description, a host that already knows how to paint.

What Salesforce shipped

Salesforce calls this Headless Experience Layer. Headless does not mean “no UI.” It means the UI is not locked to Lightning. You write a small JSON tree. Slack, ChatGPT, Claude, Agentforce, or any MCP host can render it with their own look. You do not ship a second stylesheet. You do not paste markdown and hope.

The public playground is the place to learn this with your hands. Every tutorial on that site is itself a widget. Expand the code view and you are reading the same JSON a host will render. That is not a mock. That is the runtime.

Words you will see. They are not interchangeable.
WordIn plain English
HXLSalesforce’s name for “describe the interface once, let each host paint it.”
ComponentA primitive brick: tile/text, tile/badge, tile/button, tile/card.
WidgetThose bricks composed into one useful page — our Case Next Action card.
MosaicThe JSON file. Data (model) + tiles (view) + later, actions (controller).
Semantic variantIntent, not hex. primary, warning, elevated. Claude picks Claude’s colors. Slack picks Slack’s.
MCPModel Context Protocol. The plug that lets Claude call a local tool and, here, mount a UI in the thread.
Claude DesktopThe chat app on your computer. Different from Claude Code in the terminal. This demo is the chat app.

The interesting line in our mosaic is not the heading. It is a callout that only exists when the case is actually on fire:

{
  "definition": "tile/callout",
  "meta": { "if": "{!$case.slaAtRisk}" },
  "attributes": { "variant": "warning", "title": "SLA at risk" }
}

When slaAtRisk is false, that block is not hidden with CSS. It is not in the tree. Each host decides what “absent” means. That is HXL doing the work you used to do with three UI kits.

How we used HXL to get that video

Salesforce released the language and the playground. They did not drop a finished “open this in Claude” button. The path we used is short once you see it. The README is the recipe with file names and clicks. This is the why.

flowchart LR A[Author mosaic
in HXL playground] --> B[Wrap as an
MCP app] B --> C[Turn the server on
in Claude Desktop] C --> D[Ask for the card
in a new chat]
1
Describe the card in the playground We wrote Mosaic JSON: a card, two badges, a warning callout, a primary button. Bindings look like {!$case.subject}. Variants stay semantic. We checked it on more than one host preview so we were not lying to ourselves about “write once.”
2
Keep an org-shaped copy if you want Agentforce later Same tiles, different envelope: a WidgetBundle with {!$attrs.*} and a schema. Optional for Claude. Required if the same card should live in a Salesforce org. We kept both so the idea was not trapped in a playground paste.
3
Give Claude a tool, not a JSON file Claude chat does not open Mosaic JSON by itself. It calls tools. So we wrapped the card as an MCP app: one tool, get_case_next_action, plus an HTML view the host can iframe. Think of MCP as a USB-C port. HXL is what travels through the cable.
4
Turn that tool on, then just ask Register the local server in Claude Desktop settings, fully quit the app, confirm it says running, open a new chat, and ask for the card. The README has the Settings path and the config block. You should not need a second video of the same card to understand that click.
We hit a spinner the first time. Claude wrote a confident summary. The iframe stayed blank. Two boring causes: the HTML never finished the MCP Apps handshake, and an HTTP proxy instead of native stdio. The README lists the fix. If a turn already broke, start a new chat after a full quit. The host caches the widget aggressively.

What using it feels like

In a new Claude Desktop chat, after the server shows running:

Show me the Case Next Action card

Allow the tool if Claude asks. You want the white card, not a paragraph that says “here is the card” with a loading asterisk underneath. Click Take next action if you want the widget to talk back into the thread. In this sample the buttons send a chat message. They do not update Salesforce. That is on purpose. The demo stops at “the host can render and click,” not “we wrote the case.”

The data on the card is a fictional Northwind renewal — case 00001234, owner Alex Rivera. Nothing from a real customer org is in the video or the repo.

What stays in Salesforce

Headless means the presentation can travel. It does not mean the case record should leave the platform. In a real org the same mosaic would bind through Salesforce — sharing, field-level security, audit — and Claude would be another surface, not a sidecar with a copy of the truth.

If you want to build this yourself, the story ends here and the recipe starts in the README: mosaic file, WidgetBundle, MCP server, Settings → Developer → Local MCP servers, then that same prompt.

Read the step-by-step README next. Clone, npm install in mcp/, point Desktop at server.mjs, quit with ⌘Q, ask for the card. That is the whole deploy.
